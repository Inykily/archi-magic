Baseline 921f04327f9a4fb0f2c71f605066edaa7059f1a0. Filed gap confirmed: area_report.py returns rounded room rows and grouped areas, but has no occupant-load or egress-width comparison. Issue #156 asks for room and floor loads from a supplied occupancy table and comparisons of door and stair widths along egress paths. The report remains read-only.

1. Reuse area_report.py as the normal pyRevit reader. Add opt-in occupancy_snapshot, requiring an explicit phase ID and level IDs. Collect rooms with the existing category filter. Use room.LevelId, ROOM_PHASE_ID and StorageType when resolving scope. Read Room.Area at full available precision in internal square feet. Reuse the room status helper. Read the project-selected occupancy field with the existing parameter helper, using the built-in ROOM_OCCUPANCY by default in this mode. Reject selected alternate design options rather than combine mutually exclusive rooms. Handle missing phase/level/option evidence explicitly. Record retained counts and abort before emitting totals on ambiguous scope or over 3,000 scoped rows. Use decimal string IDs to preserve precision, and avoid modifying the default output. Identify the snapshot by its SHA-256 in the second stage, with room IDs local to that snapshot.
2. Add a standalone CPython calculator under the existing skill. Require a local snapshot JSON and one reviewed criteria/routing JSON, each at most 2 MiB. Reject duplicate keys, nonfinite or excessive numbers, duplicate IDs, invalid phase/level membership, and unsupported units. Require explicit net room area basis, a project-provided occupancy factor in ft2 or m2 per person, and criteria/measurement provenance labels. Normalize and compare occupancy names by trimmed case-insensitive key, reject collisions, and use exact decimal arithmetic for conversion and per-room ceiling. Report excluded and unmapped rooms with reasons, and floor totals grouped by level ID with a completeness flag. Never use a default factor or silently count unresolved rooms as zero.
3. Accept reviewed route rows with room ID, assigned occupant count, and ordered door/stair segment IDs. A room can use multiple routes. Require positive allocations, forbid duplicate IDs within a route, and compare the allocated sum to each computed room load. For each physical segment sum the occupants on all routes that use it, once per route. Require explicit measured clear width with units (mm or in) and provenance plus operator-provided minimum and width/person criteria per segment. Compare to max(minimum, load x width/person). Compare exact values before formatting. Missing or ambiguous load, route, criteria or measurement produces an incomplete check and no overall compliance verdict. Do not derive a route from Revit's plan geometry or use nominal family widths. Even an equal-width or positive-margin result is conditional on the supplied path and criteria. No code tables, occupancy classification, permission changes, or model writes.
4. Test the real CLI with a hand-calculated floor, fractional occupancy, metric/imperial width, a shared door/stair, split load and short segment. Test unmapped rooms, wrong phase, conflicting IDs and allocations, truncated input, unsupported units and invalid width evidence. Use the actual pyRevit script entry with a DB fake to exercise opt-in and unchanged default dispatch. For closure, run the pinned reader on a disposable model and reconcile native scope, rooms and door/stair measurements against an independently calculated floor and reviewed route. Keep issue open if native qualification is unavailable. Merge only after both exact-head jobs pass. Roll back by reverting the change, with no model state to undo.
