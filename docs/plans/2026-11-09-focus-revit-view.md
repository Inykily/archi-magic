# Focus a Revit view on a selection (#158)

Baseline c723cf0c4f300c5341c96a05de994c7ec17acaa4. The filed gap is confirmed. The browser viewer has zoom controls and issue #149 has an offline section proposal, but no current native recipe creates or updates a section box or plan crop. #158 requests creation, reuse or plan crop and an independent padded-containment check.

1. Add a read-only am-safe-change query for one saved project, current selection, one explicit target action, and positive padding in internal feet. For a new 3D view, require an exact ThreeDimensional ViewFamilyType ID and unused proposed name. For reuse, require an exact existing orthographic View3D ID. For plan crop, require an exact existing ViewPlan ID. Record saved path digest, ProjectInformation.UniqueId, current selection IDs and element UniqueIds, target UID and existing box and active flag, view family type/default template, and attached sheet context. Refuse unsupported shape, split, perspective, locked, dependent, scope-box or template-controlled views. Refuse missing, view-specific or unresolved selection elements. Use the model-space element bounding box without clipping, transform all eight corners and compare the result to independent geometry in Revit. Do not silently use a link instance's entire box as a linked-element selection.
2. Calculate outside Revit using a pure Python 2.7/3-compatible module in the existing recipe workspace. Union all host-frame corners for a 3D identity-frame section box. For a plan, project points to the current crop frame, pad screen X/Y only and preserve current Z range and frame. Reject invalid frames, overlarge bounds, unreasonable padding and empty selection. Show changed target, old/new extents, selected IDs, sheet placements and ownership IDs. Refuse a workshared update when the target is owned by others or changed in central. Use the existing side-effects check and approval sequence.
3. Apply in one transaction. Re-read the same selection, document, target, frame, geometry and ownership. Recompute the plan and compare meaningful output before starting the transaction. Create with View3D.CreateIsometric, rename, set section box and activate it. For an existing isometric view set and activate the section box. For plan crop set CropBox and CropBoxActive using coordinates in the preflight frame. Verify the persisted frame, active flag and box by reading them back after regeneration before committing. Stop and roll back on mismatch. Pass dry run and real run via run_modify, show regeneration, require Keep or Discard under the host policy, and read back after Keep. The user can open the resulting view after Keep. The script leaves active view and selection alone.
4. Test pure math and stale state at the actual query/apply entry via a Revit fake. Verify rotated projection, three axes of padding, exact box containment, old plan Z, unsupported view/split, changed geometry/selection, name collision, wrong model, refusal before transaction, readback mismatch rollback and reuse. Native fixture uses known element geometry, 3D creation/reuse and rotated plan, plus Keep/Discard and unchanged state on dry run. Record Revit build and engine, exact revision, visible target scope, padding, checked extents and actual view identity. Keep #158 open until native verification. Both exact-head CI jobs and merged-source checks are separate from native acceptance. Rollback with Discard/Undo or revert the PR.

## Reviewed contract

- Ship a recipe linked from am-safe-change/SKILL.md, a native focus_view.py query/apply/verify entry with the existing workspace mechanism, and a pure focus_view_preview.py compute/compare/side-effects CLI. Emit the standard change-preview keys (including before/after, keyColumn, changedColumns, steps, ownership_ids, warnings and blocked). Accept bare or complete runtime result envelopes and an ASCII-encoded snapshot string. For creation the source type is read-only and ownership has zero existing targets; record that explicitly. Existing targets follow the ownership CLI and get a second native ownership check immediately before apply. The created view ID feeds post-Keep ownership readback.
- Require a saved writable project, exact document identity, typed Int64 IDs and full canonical preflight snapshot and intent. Refuse project families, target templates, any assigned/default view template, nonorthographic/locked reuse targets, scope-box, split/custom crop, and primary or dependent targets with crop coupling. For on-sheet targets, return a warning and bind the exact viewport/sheet IDs. Require explicit allow_placed intent plus review of model and annotation clipping effects. Keep selection/view activation separate. Any observed drift, including changed viewports or ownership, stops before the transaction. Recompute the write box from a fresh snapshot and reject user-edited coordinates. Use finite orthonormal right-handed frame and bounded extents.
- For plan crop use current CropBox-local X/Y and its existing Z. Refuse unsupported rectangular crop state before write. Re-read the actual persisted frame and extents after regeneration and require all expected bounds to agree within 1e-6 ft. Verify view active/crop-active flags separately. Use one transaction with checked Started and Committed status. Roll back only while Started on any pre-commit failure, validate RolledBack, and treat Pending or uncertain status as unresolved. On regeneration failure do no further document reads. The script never asserts that pyRevit kept a change based on its inner commit. Expose a verify query by exact returned view ID and UID, independent of the create-name preflight.
- Use real dry-run result content, including the checked box, and existing side-effect summarizer. Distinguish new view creation from a reported modification, and treat missing required telemetry as unverified. Review unexpected IDs when provided, plus categories. After dry run issue a fresh read of the original state to prove the proposed name is unused or existing box and flags are unchanged, and confirm active view and selection are unchanged. Do not run the real change if these checks fail. Use same-plan Keep/Discard under ask policy or a separate post-dry-run yes under auto policy.
- Native acceptance matrix on a disposable saved model: independently measure two asymmetric selected elements, then check create, reuse an inactive nonidentity section box, and rotated rectangular plan crop with known screen extents and unchanged depth/frame. Prove padded containment using all eight model-space source corners in the actual persisted box frame. Check native visibility independently of containment, since filters, phase, view range and category state can hide an enclosed element. Check unchanged state on dry run and Discard, exact ID/UID and readback on Keep, and stale selection/target rejection. Record Revit version/engine/revision and independent expected vs actual results before closure. Keep local/CI evidence separate.
