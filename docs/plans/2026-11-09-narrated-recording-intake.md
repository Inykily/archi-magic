## Implementation and rollout

1. Add one local Python CLI with a small reusable media module. Require a regular local MP4, trusted operator-supplied FFmpeg/ffprobe/whisper-cli and local model. No automatic install, download, server or network service. Copy a size-bounded private snapshot while hashing it and reject drift. Every decoder forces MOV, disables drefs and absolute aliases, whitelists file/pipe, disables inherited stdin and selects one audio/video stream. Reject ambiguous streams or nonzero stream/movie start times. Use a private staging directory and publish only a complete preview into a new directory. Use the tested FFmpeg protocol whitelist and local container handling, argument arrays rather than shell interpolation, input validation, timeouts, and bounded duration/resolution/file size. Bound cumulative time, byte output, number and length of clips, scenes/frames, dimensions, JSON and generated bytes. Kill and reap timed-out/overflowing processes. Decode to 16-kHz mono PCM WAV and run Whisper locally with no fallback one bounded voice window at a time. Validate ordered clip-relative milliseconds, convert to source time and label timing estimates. Fail rather than approve a missing, blank, malformed or partial transcript.
2. Use FFmpeg silencedetect at -42 dB for 0.7 seconds and scdet at 3 percent on a 4 fps, 320px sample. Both were probed on the actual fixture. Preserve frame requested time and measured PTS from showinfo. A long voice segment is chunked with visible warnings. Sample frames near voiced phrases, pauses and significant scene changes. Accept explicit click timestamps when available; ordinary MP4 does not carry reliable click events. Associate frames and timestamps with each draft item. Recognize explicit element IDs/view names from narration as candidate references only; the reviewer checks the linked frame and can correct or supply the exact reference. Do not guess a view or ID where evidence is absent. Preserve source narration as literal data. Split numbered actions or distinct speech segments into numbered candidates; route uncertainty to review rather than silently deleting text.
3. Use separate preview/items and reviewed/tasks schemas with no records key; never feed drafts to consolidate.py. Produce only unconfirmed items and evidence in preview. Run a separate review command against the preview and an explicit human-edited decision file. Require exact preview-byte digest and one valid accept/edit/reject decision per item. Reject missing, duplicate or unknown IDs/fields and blank edits. Bind preview to recording digest and frame hashes, validate controlled paths and verify evidence bytes again at review. An unresolved target must be edited with a concrete reference or rejected. Treat the result as a task proposal, not executable instructions. Output only accepted/edited tasks with source evidence. An all-rejected or ambiguous result cannot start work. Document that approval of the task list is not approval of any model write. Use the existing am-safe-change preview, dry run and Keep/Discard workflow for any later changes. The new CLI has no Revit connector or write path.
4. Test CLI contract with deterministic subprocess fixtures and run the actual tested tools on the 120-second synthetic recording. Independently verify door swing A101, floor finish A102 and ceiling tag A103; check scene changes at 40/80 seconds, speech frames and explicit click timestamps. Test a clicked view with no stated target stays unresolved until a reviewer supplies one. Verify no tasks ready before review. Verify rejection, edits, preview/frame substitution, digest mismatch, missing/duplicate decisions, output floods and stale/malformed confirmation. Keep private media, frames, transcripts and raw output on the operator's local filesystem. Do not send them to hosted prompts, logs, attachments or tools. Only the user's redacted summary can leave their computer. Keep offline CLI fixture tests in the Linux Python lane; actual media-tool acceptance is separate from Windows PowerShell CI. Use both CI jobs on the final PR head. Close only when the merged CLI passes the actual synthetic recording and documented confirmation gates.

## Assumptions, dependencies and rollback

- FFmpeg, ffprobe and whisper-cli are optional user-supplied local executables. The pinned validation commands come from the installed tools and official ffmpeg/whisper.cpp sources. The CPU test binary and model are separate temporary tools, not bundled.
- Voice activity is an estimate based on the stated silence threshold. Frame/time and source text allow the user to catch omissions or duplicate suggestions. Clip limits fail clearly instead of presenting a partial list as complete.
- No project media upload, model edits, OCR inference, OS click tracking, hosted services, background automation or global tool installs. Treat speech, frames and metadata as untrusted. Keep generated files outside the repo. Roll back by reverting the merged change, or delete the local preview folder if the user no longer needs it.

## Acceptance run

The 120-second synthetic MP4 produced exactly three numbered proposals: door swing in A101, floor finish in A102, and ceiling tag in A103. The extracted evidence included two speech pauses, scene changes at 40 and 80 seconds, and the explicit click sample at 90.5 seconds. The separate CLI rejected the blank decision template and returned three reviewed tasks after simulated accept/edit/accept, with model-write approval false. Whisper rounded the last decoded timestamp into up to 0.5 seconds of trailing padding, so the displayed source timestamp is clipped to the measured voice window.
