# Room finishing (#132)

Baseline main: 9ec93d4731be4193219aa1875e6524a4b6a09bc7. GitHub #132 asks for room-driven floor and wall finishes from type rules, door-opening avoidance and open-boundary reporting. The title includes ceilings, so keep ceiling creation in scope. Filed baseline: confirmed gap in the initial backlog audit. Existing room reporting only classifies boundary presence (`skills/am-area-report/scripts/area_report.py:61–71`). Corner guards enumerate wall inserts (`skills/am-corner-guard/scripts/place-corner-guards.py:99–119`). Neither creates room finishes.

## Approach and order

1. The first PR is a query-only Revit 2026 preflight for 1–20 explicit room IDs. It reports valid loops, holes, source IDs and actionable missing, unplaced, open or unsupported room reasons. Run the actual query entry point with a Revit stand-in and prove that it needs no transaction API. Later, extend am-safe-change with room-finish placement and mapping. Resolve explicit room IDs and type IDs, with an optional per-room parameter lookup into an explicit user mapping. A room may be skipped independently, with an actionable reason. Read level, phase and design option, actual boundary segments, source element ownership and candidate existing finishes. Return JSON-safe endpoints, a curve-type summary and stable source IDs. Reread original curves in Revit before apply. Build typed List[DB.CurveLoop] as in sync_reference_view.py:75–83 and require all loops to lie on the same horizontal plane as well as pass Autodesk BoundaryValidation. Include room holes. Report open, unplaced or unsupported room boundaries and exclude those rooms from apply.
2. Plan walls only for supported boundaries with verifiable wall source and known finish type width. Derive the interior side using room containment, not arbitrary curve direction. Use FindInserts with all four flags so embedded and shared inserts are not silently missed. Check phase and design option. Project the verified opening extent to the segment axis, clip and merge overlapping intervals, and reject pieces under Revit's short curve tolerance. Prove the full finish width remains inside the room and outside every opening. Reject ambiguous normal, slope, unclassified inserts, and openings that cross segment joins. If a door, insert, boundary link, or curve cannot be classified safely, skip that wall segment and explain why. Floors and ceilings follow closed profiles independently. Use the four-argument Floor.Create and Ceiling.Create overloads with typed profile loops. Apply and read back FLOOR_HEIGHTABOVELEVEL_PARAM and CEILING_HEIGHTABOVELEVEL_PARAM against a nonzero level. Finish walls must have room bounding off and both end joins disallowed. Cap the first run to 20 rooms and 200 planned creations.
3. Before enabling any write, validate a fixed ExtensibleStorage schema in the installed host. Store provenance per room UniqueId and finish piece, including kind, type and level. Compare actual geometry, type and level against the full expected set before every write. Treat partial, missing, copied, edited or overlapping existing pieces as conflicts. Validate the host schema and inspect pre-existing finishes. Do not enable apply if those checks cannot be proved.
4. Generate a read-only preview with exact scope, type/elevation parameters, created counts, source IDs, geometry digest and excluded rows. A document identity and digest mismatch aborts before any transaction. Require `ask` policy, scope/ownership check, user preview confirmation, dry run, independent no-change readback, actual Keep/Discard, and post-run readback per am-safe-change/SKILL.md:24–47,78–82. Test one transaction across the approved set; on failures it rolls back without preserving a partial set.
5. Publish with `Refs #132`. Run both GitHub CI jobs on the final commit. Confirm an authorized disposable Windows model and installed Revit/pyRevit versions before any host work. Use independent readback after dry run, Discard and Keep. Verify an open room, a nonzero level, holes, two adjacent rooms with a shared wall, a rotated and segment-end door, overlapping openings, unclassified inserts, rerun idempotency, prior partial sets, stale previews, and injected late failure. Compare existing walls, doors, adjacent room boundaries/areas and finishes after each run. Verify successful placement and no changes outside scope. Close only after the exact merged implementation meets these tests.

## Dependencies, checks, and limits

- Windows Revit and matching installed pyRevit transport. No authorized reachable host has been confirmed in the current Mac session. Validate the installed Revit year and pyRevit engine before relying on signatures or opening test models.
- Autodesk BoundaryValidation.IsValidHorizontalBoundary, Floor.Create and Wall.Create are documented for Revit 2026. Verify the exact Ceiling.Create overload, boundary planarity, wall centerline placement, room-bounding setting, unjoined ends, door interval/phase handling, offsets and ExtensibleStorage APIs against installed references and a disposable model.
- Verify that floor and ceiling creation do not modify dependent model elements outside the preview. Use approved non-structural finish types. Do not change base walls, doors, room boundaries, worksets, existing finish elements or shared type definitions.
- Exclude rooms and wall segments whose link, arc, topology, level, or insertion geometry cannot be proven in the first host pass. Issue acceptance needs representative supported rooms and an explicit disposition of remaining geometry cases. No project or office names or real IDs belong in this public repository.
- Rollback is one Revit transaction, host Discard or one undo entry, confirmed by independent inventory readback. Revert the feature's merge commit if deployment validation fails.
