## Dependencies, assumptions, and rollback

- Installed reader versions must support the documented API and the Python version used by CI. Establish actual import/API behavior before implementation. Use package installs only in isolated tooling and GitHub test environments.
- The workbook/schedule key fields must identify one row per record. Use composite keys if room numbers are reused. The schedule reader labels group/total rows heuristically; do not claim underlying model completeness from a grouped or filtered snapshot.
- Extract tables that have one rectangular, explicitly selected header row. Reject missing columns or duplicate keys. Scanned PDFs and complex/nonrectangular tables need a separate OCR or manual normalization workflow.
- For rollout, use a merge commit after exact-head CI. Roll back by reverting that commit. The comparison reads local documents and never saves a project document or a Revit model.
